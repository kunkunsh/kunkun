# Tauri Plugins Knowledge Base

**Generated:** 2026-01-17

## OVERVIEW

Custom Tauri plugins provide Rust-backed system APIs for extensions with granular permission-based access.

## STRUCTURE

```
packages/tauri-plugins/jarvis/
  ├── src/commands/       # 16 modules (system, fs, db, extension, file_transfer)
  ├── src/server/         # HTTP/REST/gRPC server (axum/tonic)
  ├── src/syscmds/        # Platform-specific (mac/linux/windows)
  ├── src/model/          # Data models, state
  └── permissions/        # Tauri capability definitions
vendors/
  ├── tauri-plugin-network/      # Network interfaces & scanning
  ├── tauri-plugin-system-info/  # CPU/memory/battery
  ├── tauri-plugin-keyring/      # Secure credentials
  └── tauri-plugin-user-input/   # Keyboard/mouse simulation
```

## CONVENTIONS

**Plugin entry:** `lib.rs` → `init<R>() → TauriPlugin<R>`  
**State:** `app.manage(State::new())` in setup  
**Commands:** `#[tauri::command]` in `commands/`  
**Permissions:** TOML files, autogenerated via `build.rs`

```rust
#[tauri::command]
pub fn fn_name(arg: Type) -> Result<Ret, Err> { /* impl */ }
// Register: .invoke_handler(tauri::generate_handler![fn_name])
```

**Platform:** `#[cfg(target_os = "macos")] mod mac;`  
**Dependencies:** `axum`/`tonic` (servers), `mac-security-rs`/`sysinfo` (system), `tokio` (async), `rustls`/`openssl` (TLS)

## ANTI-PATTERNS

**FORBIDDEN:** Expose commands without permissions, blocking I/O in async, store secrets in state, register without `#[tauri::command]`  
**AVOID:** Direct window manipulation, platform code in shared modules

## GOTCHAS

- Regenerate permissions: `pnpm build` updates `permissions/autogenerated/`
- RSA keys session-based (in-memory only)
- SQLite access through commands only

## COMMANDS

```bash
cargo build -p tauri-plugin-jarvis
cargo test -p tauri-plugin-jarvis
```

**Add command:** Implement → Register → Add to `permissions/all.toml` → Rebuild
